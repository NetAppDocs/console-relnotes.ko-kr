==== Kubernetes 워크로드 개선 사항

이번 릴리스에서 NetApp Backup and Recovery는 Kubernetes 워크로드에 대해 다음과 같은 향상된 기능을 제공합니다:

* *Trident Protect 26.10*: 이번 릴리스에는 Trident Protect 26.10가 포함되어 있습니다.
* *ontap-nas-economy 및 ontap-san-economy 드라이버 지원*: 이제 NetApp Trident `ontap-nas-economy` 드라이버(Qtree) 및  `ontap-san-economy` 드라이버(LUN)로 프로비저닝된 영구 볼륨 클레임(PVC)을 보호할 수 있습니다. 이코노미 드라이버를 사용하여 PVC를 보호하면 기본 FlexVol 또는 LUN 전체가 보호됩니다. 이러한 백업에서 개별 PVC를 복원할 수 있습니다.
* *Kubernetes 인식 알림*: 이제 알림이 볼륨당 한 번이 아닌 Kubernetes 애플리케이션당 한 번 전송됩니다.
* *볼륨 그룹 스냅샷 지원*: 이제 Kubernetes 애플리케이션을 정의할 때 볼륨 그룹을 생성할 수 있습니다. 볼륨 그룹을 사용하면 여러 볼륨을 함께 스냅샷하여 크래시 일관성을 유지하는 세트를 만들 수 있으므로 그룹 내 모든 볼륨에서 데이터 일관성을 보장합니다.
* *S3 호환 오브젝트 스토리지 지원*: 이제 백업 대상 자격 증명을 추가하고 보호 정책을 구성하여 Kubernetes 애플리케이션 리소스 및 데이터를 S3 호환 오브젝트 스토리지에 백업할 수 있습니다.


Kubernetes 워크로드 보호에 대한 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["NetApp Backup and Recovery를 사용하여 Kubernetes 워크로드를 보호하는 방법에 대해 알아보십시오."^]을 참조하세요.

ONTAP Volumes 워크로드 보호에 대한 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["NetApp Backup and Recovery를 사용한 ONTAP 볼륨 보호에 대해 알아보십시오"^]를 참조하십시오.

=== Cloud Volumes ONTAP



==== Azure의 Cloud Volumes ONTAP 9.19.1

이제 NetApp Console을 사용하여 Azure에서 Cloud Volumes ONTAP 9.19.1의 일반 출시(GA) 버전을 배포하고 관리할 수 있습니다.

콘솔은 2026년 8월부터 AWS 및 Google Cloud에서 Cloud Volumes ONTAP 9.19.1을 지원합니다.

https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-new.html["Cloud Volumes ONTAP 9.19.1 릴리스 노트"^]



==== Cloud Volumes ONTAP용 Azure 호스트 암호화

Cloud Volumes ONTAP 9.19.1 GA부터 필수 조건을 충족하는 새로운 Azure 단일 노드 및 고가용성(HA) 배포에 대해 Azure 호스트 암호화가 기본적으로 활성화됩니다. 이 기능은 데이터가 호스트에 기록되고 호스트에서 읽힐 때 임시 디스크 및 관련 호스트 수준 캐시 등 VM을 호스팅하는 물리적 서버의 데이터를 암호화합니다.

Azure에 Cloud Volumes ONTAP을 배포하기 전에 환경이 다음 필수 조건을 충족하는지 확인하십시오.

* 해당  `EncryptionAtHost` 기능이 Azure 구독에 등록되었습니다.  https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli["Microsoft 설명서: 호스트에서 암호화 활성화"^]을(를) 참조하십시오.
* 선택한 VM 인스턴스 유형은 Azure 지역의 호스트에서 암호화를 지원합니다.  https://learn.microsoft.com/en-us/azure/virtual-machines/linux/disks-enable-host-based-encryption-cli#finding-supported-vm-sizes["Microsoft 설명서: 지원되는 VM 크기 찾기"^]을(를) 참조하십시오.


다음 사항에 유의하십시오:

* 추가 구성이 필요하지 않습니다.
* 이러한 필수 조건을 충족하지 못하면 Cloud Volumes ONTAP 배포에 대해 호스트에서의 Azure 암호화가 활성화되지 않습니다.
* 호스트 암호화는 Azure에만 적용되며 AWS 또는 Google Cloud에는 적용되지 않습니다.


Microsoft 문서: https://learn.microsoft.com/en-us/azure/virtual-machines/disks-enable-host-based-encryption-portal["Azure 포털을 사용하여 호스트 암호화를 통해 종단 간 암호화를 활성화하십시오."^]



==== Azure 및 Google Cloud의 Cloud Volumes ONTAP 클러스터에서 백엔드 네트워크 암호화

Cloud Volumes ONTAP 9.19.1 이상 버전은 Azure 및 Google Cloud의 고가용성(HA) 구성에 대한 백엔드 클러스터 네트워크 암호화를 지원합니다.

클러스터 네트워크 암호화를 활성화하면 클러스터 성능에 영향을 미칠 수 있습니다. 주의를 기울여 이 기능을 활성화하기 전에 환경이 추가 오버헤드를 수용할 수 있는지 확인하십시오.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-enable-cluster-encryption.html["Cloud Volumes ONTAP 클러스터에서 백엔드 네트워크 암호화를 활성화합니다."^]



==== Azure 예약 유지 관리 중 중단을 줄일 수 있는 기능

예정된 유지 관리 중에 Azure는 Cloud Volumes ONTAP HA 쌍의 VM을 잠시 일시 중지할 수 있습니다. ONTAP은 이 일시 중지를 노드 장애로 인식하고 스토리지 작업을 파트너 노드로 이동한 다음 VM이 다시 시작될 때 다시 이동시킬 수 있습니다(테이크오버 및 반환). 이 프로세스는 노드 장애가 없는 경우에도 활성 클라이언트 연결을 중단시킬 수 있습니다.

Cloud Volumes ONTAP 9.19.1 이상 버전에서는 Azure 예약 유지 관리로 인해 HA 쌍이 일시 중단되는 동안 자동으로 테이크오버 및 기브백을 시작하지 않고 계속 작동하도록 하는 선택적 설정을 활성화할 수 있습니다.


NOTE: 이 기능은 Cloud Volumes ONTAP 9.19.1 버전에서 공개 미리 보기로 제공됩니다.

https://docs.netapp.com/us-en/storage-management-cloud-volumes-ontap/task-azure-prevent-freeze.html["Azure 유지 관리 중 Cloud Volumes ONTAP HA 쌍의 중단을 방지합니다."^]

==== ONTAP Volumes 워크로드 개선 사항

이번 릴리스에서 ONTAP Volumes 워크로드는 다음과 같은 미리 보기 개선 사항을 도입합니다.

NetApp Backup and Recovery for dark sites는 ONTAP Volumes 워크로드만 지원합니다.
* *볼륨 복원 작업 취소*: 이제 작업 모니터링 페이지에서 진행 중인 ONTAP 볼륨 복원 작업을 취소할 수 있어, 실행 시간이 길거나 속도가 느린 작업을 더욱 쉽게 관리할 수 있습니다.

* *NetApp AFX 지원*: 이제 2노드 및 4노드 NetApp AFX 클러스터에서 호스팅되는 볼륨을 보호할 수 있습니다.

=== Cloud Volumes ONTAP



==== 프라이빗 모드 배포에서 용량 기반 라이선스 지원

이제 AWS, Azure 및 Google Cloud에서 용량 기반 라이선스를 사용하여 프라이빗 모드로 Cloud Volumes ONTAP 시스템을 배포할 수 있습니다.

NetApp은 프라이빗 모드에서 용량 기반 라이센스 모델을 위해 Essentials 패키지만 지원합니다. NetApp에서 용량 기반 BYOL(Bring-Your-Own License) Essentials 패키지를 구매하여 배포 시 시스템에 할당하십시오. 최초 500GiB 사용량은 라이선스 요금에 포함되지 않습니다. 워크로드 요구 사항이 증가함에 따라 추가 패키지를 구매할 수 있습니다.

NetApp은 모든 프라이빗 모드 Cloud Volumes ONTAP 구축에 용량 기반 라이선스를 권장합니다. 노드 기반 라이선스를 사용하는 기존 프라이빗 모드 구축 환경이 있는 경우, NetApp에서 Essentials 패키지를 구매하여 용량 기반 라이선스로 전환할 수 있습니다. 이러한 새로운 구축 기능과 전환 옵션을 통해 NetApp은 노드 기반 라이선스에서 용량 기반 라이선스로 점진적으로 전환하려는 계획을 추진하고 있습니다.

=== 재해 복구



==== NetApp Disaster Recovery에서 Kubernetes 지원 기능이 이제 정식 출시(GA)되었습니다.

NetApp Disaster Recovery에서 Kubernetes 기반 워크로드 지원이 정식 출시(GA)되었습니다. Kubernetes 기반 워크로드 지원을 통해 OpenShift 가상화 환경을 포함한 Kubernetes 클러스터에서 실행되는 애플리케이션을 보호할 수 있습니다. Disaster Recovery는 Trident Protect에서 현재 지원하는 모든 버전의 Kubernetes를 지원하므로 컨테이너화된 애플리케이션에 대한 원활한 통합과 강력한 재해 복구 기능을 제공합니다.

Kubernetes 기반 워크로드 보호를 시작하려면 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/get-started/task-kubernetes-requirements.html["NetApp Disaster Recovery를 위한 Kubernetes 요구 사항"^]을(를) 참조하십시오.



==== 리소스 변환

재해 복구 기능이 이제 리소스 변환을 지원하여 장애 조치 중에 워크로드의 모든 측면을 수정할 수 있습니다. 이 기능은 재해 복구 이벤트 중에 워크로드를 다양한 환경 및 구성에 맞게 조정할 수 있는 유연성을 제공합니다.

리소스 변환은 복제 계획을 생성할 때 적용됩니다. 새 설정 페이지에서 리소스 변환을 생성, 편집 및 삭제할 수 있습니다. 자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/task-resource-transformation.html["리소스 변환 관리"^]을 참조하십시오.



==== 스크립트 실행

이제 장애 조치 워크플로에 사용자 지정 스크립트를 삽입하여 애플리케이션의 일시 중지 및 재개를 조정할 수 있습니다. 이 기능을 통해 스냅샷이 복제되고 적절하게 복원되기 전에 애플리케이션이 제대로 준비되도록 하여 장애 조치 후에도 원활하게 운영을 재개할 수 있습니다.

사용자 지정 스크립트를 삽입하는 방법을 알아보려면 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/task-replication-plan-kubernetes.html["복제 계획 생성"^]을 참조하십시오.



==== 새 워크로드 페이지

재해 복구 기능에 워크로드 페이지가 추가되어 검색된 모든 워크로드와 해당 보호 상태를 한눈에 확인할 수 있습니다. 이 워크로드 페이지를 통해 워크로드를 더욱 효과적으로 모니터링하고 관리할 수 있습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/dashboard-view.html["Disaster Recovery에서 상태 및 보호 상태 검토"^]을 참조하십시오.



==== 설정 페이지

이제 재해 복구 기능에 리소스 변환 템플릿과 AppVaults를 중앙에서 관리할 수 있는 설정 페이지가 제공됩니다. 이 페이지는 재해 복구 계획의 핵심 구성 요소를 구성하고 관리할 수 있는 단일 인터페이스를 제공합니다. 설정 페이지의 옵션에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/task-resource-transformation.html["리소스 변환 관리"^] 및 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/task-appvault.html["AppVaults 관리"^]을 참조하십시오.



==== 전반적인 개선

NetApp Disaster Recovery는 더욱 원활하고 오류 없는 사용자 경험을 보장하기 위해 복제 계획 생성 페이지에 향상된 유효성 검사 기능을 도입했습니다.

Disaster Recovery는 간헐적인 요청 시간 초과를 허용하도록 서비스의 복원력을 높여 UI의 전반적인 성능과 안정성을 향상시켰습니다.

==== 개선된 대시보드

Disaster Recovery 대시보드가 새롭게 개선되어 전체 Disaster Recovery 환경을 한눈에 파악할 수 있는 향상된 사용자 경험을 제공합니다. 새로운 대시보드에는 다음이 포함되어 있습니다.

* *통합 워크로드 가시성* — 단일 화면에서 VMware 및 Kubernetes 워크로드와 기본 인프라 상태를 모두 모니터링할 수 있습니다.
* *사전 예방적 문제 표시* — 대시보드가 이제 환경 문제를 자동으로 강조 표시하여 더 빠른 진단과 문제 해결 시간 단축을 지원합니다.
* *용량 활용률* — 용량 관련 지표가 이제 대시보드에 직접 표시되어 리소스 소비량을 더 쉽게 파악할 수 있습니다.


자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/dashboard-view.html["대시보드에서 NetApp Disaster Recovery 계획의 상태를 확인합니다"^]을 참조하십시오.

환경 전반의 Disaster Recovery 활동에 대한 보다 심층적인 인사이트를 제공하도록 보고 기능이 확장되었습니다.

* 각 보고서는 지정된 기간 동안의 활동에 대한 완전한 요약을 제공하여 Disaster Recovery 환경에서 발생하는 모든 이벤트를 완벽하게 파악할 수 있도록 합니다.


자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/reports.html["NetApp Disaster Recovery 보고서 생성"^]을 참조하십시오.

Disaster Recovery는 사용자 수준 작업 로깅을 통해 작업의 책임성과 감사 가능성을 향상시켰습니다. 이제 실행되는 모든 작업에는 작업을 시작한 사용자가 기록되어 규정 준수 및 문제 해결을 위한 명확한 감사 추적을 제공합니다. Disaster Recovery에 의해 자동으로 트리거되는 작업은 "system"으로 식별되어 사용자 시작 활동과 서비스 시작 활동을 쉽게 구분할 수 있습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["NetApp Disaster Recovery 작업 모니터링"^]을 참조하십시오.
