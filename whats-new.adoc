[[backup-and-recovery]]
=== 백업 및 복구



==== 일반 NetApp Backup and Recovery 기능 향상

* *NetApp Console 로컬 배포 지원*: 이번 NetApp Backup and Recovery 릴리스는 NetApp Console 로컬 배포를 미리 보기 상태로 지원합니다.
* *90일 작업 보존*: 이제 Backup and Recovery가 작업 모니터에서 작업 정보를 90일 동안 보존합니다.




==== VMware 워크로드 개선 사항

이번 릴리스에서 VMware 워크로드는 다음과 같은 개선 사항을 도입했습니다.

* *SAN VM에 대한 대체 위치 복원 지원*: 이제 SAN 기반 VM 백업을 다른 위치로 복원할 수 있습니다.
* *여러 백업 삭제 지원*: 이제 한 번에 여러 백업을 삭제할 수 있습니다.


VMware 워크로드 보호에 대한 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-vmware-protect-overview.html["VMware 워크로드 보호 개요"]을 참조하십시오.



==== Kubernetes 워크로드 개선 사항

이번 릴리스에서 Kubernetes 워크로드는 다음과 같은 개선 사항을 도입했습니다.

* *에어갭 리소스에 대한 미리 보기 지원*: NetApp Console 로컬 배포에서 NetApp Backup and Recovery를 실행하는 경우 에어갭 Kubernetes 리소스를 검색, 보호 및 복원할 수 있습니다. 이 기능은 이번 릴리스에서 미리 보기로 제공됩니다.


Kubernetes 워크로드 보호에 대한 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Kubernetes 워크로드 보호 개요"]을 참조하세요.



==== ONTAP Volumes 워크로드 개선 사항

이번 릴리스에서 ONTAP Volumes 워크로드는 다음과 같은 개선 사항을 도입했습니다.

* *복원 작업을 백업보다 우선 순위 지정*: 이제 가상 머신이나 파일을 복원할 때 복원 작업을 백업 작업보다 우선 순위로 지정할 수 있습니다.
* *Backup and Recovery 활성화 없이 ONTAP 시스템 및 볼륨 검색*: 이제 Backup and Recovery를 활성화하지 않고도 시스템과 볼륨을 검색할 수 있습니다.


ONTAP Volumes 워크로드 보호에 대한 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/prev-ontap-protect-overview.html["ONTAP 볼륨 워크로드 보호 개요"]를 참조하십시오.



[[data-classification]]
=== 데이터 분류



==== 활성 스캔 탭으로 스캔 관리 향상

데이터 분류 기능의 구성 메뉴에 *활성 스캔* 탭이 추가되어 스캔 관리가 더욱 편리해졌습니다. 활성 스캔 탭에서는 스캔을 활성화한 모든 볼륨을 한눈에 볼 수 있으며, 익숙한 필터를 사용하여 리소스를 정렬할 수 있습니다. 또한, 이 탭은 스캔 우선순위 지정, 스캔 일시 중지, 오류 검토를 위한 중앙 위치를 제공합니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-data-classification/task-managing-repo-scanning.html["스캔 관리"^]을 참조하십시오.



[[disaster-recovery]]
=== 재해 복구



==== 개선된 대시보드

Disaster Recovery 대시보드가 새롭게 개선되어 전체 Disaster Recovery 환경을 한눈에 파악할 수 있는 향상된 사용자 경험을 제공합니다. 새로운 대시보드에는 다음이 포함되어 있습니다.

* *통합 워크로드 가시성* — 단일 화면에서 VMware 및 Kubernetes 워크로드와 기본 인프라 상태를 모두 모니터링할 수 있습니다.
* *사전 예방적 문제 표시* — 대시보드가 이제 환경 문제를 자동으로 강조 표시하여 더 빠른 진단과 문제 해결 시간 단축을 지원합니다.
* *용량 활용률* — 용량 관련 지표가 이제 대시보드에 직접 표시되어 리소스 소비량을 더 쉽게 파악할 수 있습니다.


자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/dashboard-view.html["대시보드에서 NetApp Disaster Recovery 계획의 상태를 확인합니다"^]을 참조하십시오.



==== 개선된 보고서

환경 전반의 Disaster Recovery 활동에 대한 보다 심층적인 인사이트를 제공하도록 보고 기능이 확장되었습니다.

* VMware 워크로드, Kubernetes 워크로드 또는 둘 다를 대상으로 보고서를 생성하여 대상에 맞게 보고서를 맞춤 설정할 수 있는 유연성을 제공합니다.
* 각 보고서는 지정된 기간 동안의 활동에 대한 완전한 요약을 제공하여 Disaster Recovery 환경에서 발생하는 모든 이벤트를 완벽하게 파악할 수 있도록 합니다.


자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/reports.html["NetApp Disaster Recovery 보고서 생성"^]을 참조하십시오.



==== 사용자 작업 로깅

Disaster Recovery는 사용자 수준 작업 로깅을 통해 작업의 책임성과 감사 가능성을 향상시켰습니다. 이제 실행되는 모든 작업에는 작업을 시작한 사용자가 기록되어 규정 준수 및 문제 해결을 위한 명확한 감사 추적을 제공합니다. Disaster Recovery에 의해 자동으로 트리거되는 작업은 "system"으로 식별되어 사용자 시작 활동과 서비스 시작 활동을 쉽게 구분할 수 있습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/monitor-jobs.html["NetApp Disaster Recovery 작업 모니터링"^]을 참조하십시오.



==== 성능 및 리소스 최적화

시스템 리소스 소비를 전반적으로 줄이고 Disaster Recovery 작업 전반의 성능을 향상시키기 위해 다양한 내부 개선 사항이 적용되었습니다.

==== AWS Marketplace에서 Cloud Volumes ONTAP의 간편한 온보딩 소개

NetApp은 AWS Marketplace에서 Cloud Volumes ONTAP을 위한 간소화된 온보딩 워크플로를 도입하여 수동 작업과 온보딩 과정의 마찰을 줄였습니다.

이전에는 AWS Marketplace에서 Cloud Volumes ONTAP을 배포하려면 여러 화면을 탐색하고 역할, 정책 및 자격 증명을 수동으로 구성해야 했습니다. 이로 인해 온보딩 속도가 느리고 오류 발생 가능성이 높았습니다.

새로운 온보딩 워크플로는 다음과 같은 기능을 통해 마켓플레이스 구독에서 완벽하게 작동하는 Cloud Volumes ONTAP 환경으로의 전환을 간소화합니다.

. AWS Marketplace의 Cloud Volumes ONTAP 전용 상품 목록 구독: AWS Marketplace에서 Cloud Volumes ONTAP 독립형 상품 목록을 구독하고, 구독을 구매한 후, AWS 계정을 설정합니다(계정이 없는 경우).
. NetApp 콘솔의 안내 경로: NetApp 콘솔에서 계정을 설정하면 콘솔이 자동으로 배포 여정을 안내하며, 오른쪽 측면에 안내 경로를 표시합니다. 콘솔을 종료해야 하는 경우 나중에 안내 경로를 다시 시작할 수 있습니다.
. 구독 연동: 구독을 콘솔에 자동으로 연동하여 수동으로 연결하는 번거로움을 줄일 수 있습니다.
. AWS 자격 증명 구성을 사용한 Console 에이전트 배포: 필요한 AWS 역할을 자동으로 생성할 수 있습니다. 이 프로세스는 필요한 역할과 정책이 포함된 AWS CloudFormation 스택을 AWS 계정에 배포하여 검토할 수 있도록 한 다음, NetApp Console과 연결하여 수동 IAM 설정을 제거합니다. 그런 다음 에이전트 구성, 네트워킹 및 보안 그룹 설정을 진행하여 에이전트 배포를 시작할 수 있습니다.
. AWS에 새로운 Cloud Volumes ONTAP 시스템 배포:  `Quick create` 마법사로 바로 이동하여 더욱 빠르고 간편하게 Cloud Volumes ONTAP를 배포할 수 있습니다.

==== Cloud Volumes ONTAP HA 에서 차세대 Google Cloud VM 지원

9.19.1에서 NetApp은 Cloud Volumes ONTAP 고가용성(HA) 배포를 N2 VM에서 차세대 Google Cloud C3 시리즈 VM으로 전환하여 더욱 빠르고 확장 가능한 환경을 제공합니다.


NOTE: 이 지원은 단일 가용 영역(AZ) 고가용성(HA) 배포에만 적용됩니다.

이제 Google Cloud에서 Cloud Volumes ONTAP 9.19.1 이상 버전을 배포할 때 C3 시리즈 VM을 활용할 수 있습니다. 이러한 VM은 향상된 성능과 더 높은 용량 한도를 제공합니다. Google Virtual NIC(gVNIC)와 Hyperdisk Balanced 디스크를 사용하여 집약적인 워크로드에서 동적인 성능을 제공합니다.

Cloud Volumes ONTAP 시스템이 9.19.1 이상 버전인 경우, 단일 AZ에 간편하게 배포할 수 있도록 사전 구성된 패키지는 자동으로 C3 VM을 사용하며, 워크로드 요구 사항에 따라 IOPS 및 처리량 매개변수를 사용자 지정할 수 있습니다. 마찬가지로, 애그리게이트를 생성할 때 Google Cloud에서 성능과 확장성을 향상시키기 위해 Zonal Hyperdisk Balanced 디스크를 추가할 수 있습니다. 또한 기본 Flash Cache 지원을 위해 C3 시리즈 머신의 LSSD 버전을 선택할 수도 있습니다.

다음 사항에 유의하십시오:

* Cloud Volumes ONTAP 배포 환경에서는 C3 VM을 N2-series VM으로 또는 그 반대로 변경할 수 없습니다. 하지만 C3 제품군 내의 다른 변형 인스턴스 유형 간에는 전환이 가능합니다.
+

NOTE: C3 제품군 내에서 인스턴스 유형을 변경하는 데 걸리는 시간은 연결된 데이터 디스크 수에 따라 달라질 수 있습니다. 성능 저하를 방지하려면 사전에 구성을 계획하십시오.

* 인스턴스 유형을 변경할 때 대상 VM으로 c3-standard-44 또는 c3-standard-88과 해당 로컬 SSD(LSSD) 변형을 선택하면 Google 네트워크 서비스 송신 네트워크 계층이 자동으로 _Tier-1_로 적용됩니다. 다른 C3 변형으로 되돌리면 송신 네트워크 계층은 _Standard_로 설정됩니다.
+

NOTE: 송신 네트워크 계층을 _Tier-1_로 변경하면 추가 비용이 발생합니다. 배포 및 업그레이드 계획을 적절히 수립하십시오.

* C3의 LSSD 변형을 선택하면 Flash Cache가 기본적으로 활성화됩니다. 대상 변형이 Flash Cache를 지원하더라도 Cloud Volumes ONTAP 배포 환경에서는 C3 LSSD 변형 간에 전환할 수 없습니다.
* C3 VM에서 새 애그리게이트와 기존 애그리게이트 모두에 볼륨을 추가할 수 있습니다.
* N2 VM 유형의 Cloud Volumes ONTAP 시스템을 C3 VM 유형으로 복제할 때 디스크 유형은 기본적으로 Hyperdisk Balanced로 설정됩니다.
* NetApp Console 또는  `PUT /gcp/ha/aggregates/{workingEnvironmentId}/{aggregateName}` API를 사용하여 애그리게이트를 추가할 때 IOPS 및 처리량 설정을 변경할 수 있습니다.

==== Cloud Volumes ONTAP의 액세스 역할 소개

NetApp은 Cloud Volumes ONTAP에 대한 ID 및 액세스 관리(IAM) 역할을 도입하여 역할 기반 액세스 제어(RBAC)를 통해 보안을 강화하고 규정 준수를 간소화합니다. 사용자는 NetApp Console에 기존 자격 증명을 사용하여 로그인하고 Cloud Volumes ONTAP 작업을 계속 수행할 수 있습니다. 그러나 이제 인증은 ID 페더레이션을 통해 이루어지므로 Console 관리자가 이러한 기능을 더욱 세밀하게 제어할 수 있습니다. 모든 사용자는 Cloud Volumes ONTAP에서 작업을 수행하려면 다음 역할 중 하나를 보유해야 합니다. 역할이 없으면 사용자는 Cloud Volumes ONTAP 인스턴스를 보거나 액세스할 수 없습니다.

* *Cloud Volumes ONTAP 뷰어*: Cloud Volumes ONTAP 화면 및 탭에 대한 읽기 전용 액세스 권한을 부여합니다. 이 역할에서는 특정 화면 및 작업 버튼이 비활성화됩니다.
* *Cloud Volumes ONTAP operator*: 볼륨 추가, 스토리지 관리, 복제 구성과 같은 일상적인 관리 작업을 지원합니다.
* *Cloud Volumes ONTAP admin*: 모든 Cloud Volumes ONTAP 작업에 대한 전체 액세스 권한을 제공합니다.


Console 관리자는 *Administration > Identity*에서 Cloud Volumes ONTAP 사용자에게 역할을 할당합니다. 역할 권한은 사용자의 소속 조직을 기준으로 하며 해당 조직 내의 모든 Cloud Volumes ONTAP 시스템에 적용됩니다.

Cloud Volumes ONTAP은 각 사용자의 권한을 로컬 캐시에 저장하여 RBAC를 적용하며, 이 캐시는 매시간 자동으로 갱신됩니다. 사용자에게 새 역할이 할당되거나 기존 역할이 변경되면 변경 사항이 적용되는 데 최대 1시간이 소요될 수 있으며, 이후 해당 역할에서 허용된 모든 워크플로가 활성화됩니다.


NOTE: 콘솔 에이전트를 처음 배포하거나 기존 콘솔 에이전트를 Console 4.9.0 이상 버전으로 업그레이드할 때, 일회성 시딩 프로세스가 조직의 모든 기존 사용자에게 Cloud Volumes ONTAP 역할을 자동으로 할당합니다. 이 프로세스는 완료하는 데 최대 30분이 소요될 수 있습니다. 완료되면 콘솔은 기존 사용자에게 적절한 역할을 할당합니다.

Cloud Volumes ONTAP 역할은 Amazon Web Service(AWS), Microsoft Azure(Azure) 및 Google Cloud 환경에 적용됩니다.

이제 Keystone 대시보드의 모든 화면에서 화면 오른쪽 하단에 고정된 새 *Feedback* 탭을 사용하여 피드백을 제공할 수 있습니다. 이 탭을 클릭하면 사용 경험을 공유하고 의견을 NetApp에 직접 제출할 수 있는 패널이 열립니다.



==== 용량 사용량 및 구독 만료에 대한 알림 개선

시스템에서 생성되는 모니터링 기능을 통해 용량 사용량 및 구독 만료에 대한 더욱 세분화된 알림을 받을 수 있습니다.

구독 만료와 관련하여 이제 알림은 만료일 180일, 90일, 60일, 30일, 7일 전의 다섯 가지 임계값에서 발생하며, 만료일이 가까워질수록 알림의 심각도가 정보 제공 수준에서 심각 수준으로 높아집니다.

용량 사용량에 대한 버스트 알림 임계값이 이제 고정된 20%가 아닌 구독의 약정 버스트 비율을 기준으로 합니다. 예를 들어 약정 버스트가 40%인 경우 약정 용량 사용률이 140%에 도달하면 심각한 알림이 발생합니다.

자세한 내용은 https://docs.netapp.com/us-en/keystone-staas/integrations/monitoring-alert-monitors.html["Keystone 구독에 대한 알림 모니터를 보고 생성하세요."]을 참조하십시오.

=== 랜섬웨어 복원력



==== 보호 전략을 위한 향상된 유연성

Ransomware Resilience은 이제 랜섬웨어 탐지 전략을 선택하는 데 더 많은 유연성을 제공합니다. 이전에는 모든 랜섬웨어 보호 전략에 암호화 탐지가 포함되어야 했습니다. 이제 사용자 행동 탐지만으로 구성된 랜섬웨어 보호 전략을 활성화할 수 있습니다.

보호 전략에는 암호화 감지_와_ 의심스러운 사용자 행동 감지가 모두 포함될 수 있습니다. 파일 확장자 차단 기능 또한 모든 보호 전략에 추가할 수 있습니다.

기존 정책의 보호 전략 일부를 비활성화하면 이전 정책 버전에서 생성된 기존 경고는 "해결됨"으로만 표시할 수 있으며 "무시됨"으로는 표시할 수 없습니다. 예를 들어 암호화 감지 및 의심스러운 사용자 동작을 포함하는 보호 전략이 있었지만 암호화 감지를 비활성화한 경우 해당 워크로드에 대한 기존 암호화 경고만 해결할 수 있습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["NetApp Ransomware Resilience 보호 전략으로 워크로드를 보호하세요"^]를 참조하십시오.



==== SOAR 플레이북 개선 사항

Ransomware Resilience SOAR 플레이북에 이제 사용자를 차단하거나 볼륨을 오프라인으로 전환한 후 복구 단계가 포함되어 있습니다. 해당 작업이 랜섬웨어 위협이 아닌 것으로 판단되면 볼륨을 다시 온라인 상태로 전환하고 사용자 차단을 해제할 수 있습니다.

link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/reference-soar.html["SOAR 플레이북 통합"^].

=== Cloud Volumes ONTAP



==== AWS의 Cloud Volumes ONTAP용 새 EC2 인스턴스 지원

Cloud Volumes ONTAP 9.16.1 이상 버전은 AWS에서 신규 및 기존 단일 노드와 고가용성(HA) 쌍 배포 모두에 대해 M6id 및 M6idn EC2 인스턴스 제품군을 지원합니다. 이러한 6세대 인스턴스는 5세대 범용 시스템에 비해 더 빠른 처리 속도, 강력한 네트워킹 기능 및 향상된 성능을 제공합니다.

* *M6id 인스턴스*: 고속 저지연 로컬 NVMe 스토리지를 통해 컴퓨팅 성능과 메모리 용량의 균형을 제공합니다. 모든 M6id 인스턴스 크기는 Flash Cache를 지원합니다. 이러한 인스턴스는 데이터 로깅 및 미디어 처리와 같은 워크로드에 적합합니다.
* *M6idn 인스턴스*: M6id 인스턴스와 동일한 로컬 NVMe 스토리지 기능을 제공합니다. 모든 M6idn 인스턴스 크기는 Flash Cache를 지원합니다.


고성능 또는 메모리 집약적인 워크로드에는 m6id.xlarge, m6id.2xlarge, m6idn.xlarge 및 m6idn.2xlarge 인스턴스 유형을 권장하지 않습니다. 이러한 워크로드에는 코어 개수와 메모리 용량이 더 큰 인스턴스 유형을 사용하십시오.

자세한 내용은 https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-configs-aws.html["AWS에서 Cloud Volumes ONTAP에 대해 지원되는 구성"^]을 참조하세요.

=== 랜섬웨어 복원력



==== Google Cloud NetApp Volumes 지원(미리 보기)

랜섬웨어 복원력이 이제 Google Cloud NetApp Volumes 시스템을 지원하여 Google Cloud NetApp Volumes에서 발생하는 랜섬웨어 위협을 효율적으로 탐지하고 대응할 수 있습니다. 검색을 수행하면 랜섬웨어 복원력이 Google Cloud NetApp Volumes 시스템의 워크로드를 자동으로 표시합니다. 시스템이 검색되면 랜섬웨어 복원력 대시보드에 표시됩니다. 랜섬웨어 복원력의 Google Cloud NetApp Volumes 지원은 현재 미리 보기로 제공됩니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/concept-ransomware-resilience.html["랜섬웨어 복원력에 대해 알아보세요"^]을 참조하세요. Google Cloud NetApp Volumes 지원 범위에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-reference-limitations.html["랜섬웨어 복원력의 한계"^]을 참조하세요.



==== 클린 복원 기능 향상

이제 클린 복원에서 보고서 기능을 지원합니다. 보고서를 통해 클린 복원 결과를 검토하고 평가할 수 있으며, 해당 정보를 CSV 파일로 오프라인에 저장할 수 있습니다.

이제 클린 복원 시 분석 중지 기능도 지원합니다. 분석을 중지하면 클린 복원을 다시 시작해야 합니다.

보고서에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-reports.html["Ransomware Resilience에서 보고서 다운로드"^]를 참조하십시오. 복구에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore-recover.html["깔끔한 복원을 통해 워크로드 복구"^]를 참조하십시오.
