=== 재해 복구



==== Kubernetes 업데이트

재해 복구 기능은 Kubernetes 기반 워크로드에 대해 다음과 같은 변경 사항을 도입했습니다.



===== 사이트 메뉴에서 Trident Protect 관리

이제 재해 복구 UI의 사이트 메뉴에서 Trident Protect를 직접 관리할 수 있습니다. Trident Protect를 업그레이드하거나 재해 복구에서 제거하여 Kubernetes 리소스 관리를 간소화할 수 있습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/manage.html["사이트 관리"^]을 참조하십시오.



==== VMware 업데이트

재해 복구 기능은 VMware 기반 워크로드에 대해 다음과 같은 변경 사항을 도입했습니다.



===== 빈 데이터스토어 장애 조치

이제 빈 데이터스토어를 포함하는 복제 계획을 해당 데이터스토어를 계획에서 제외하거나 강제로 장애 조치를 수행하지 않고도 성공적으로 장애 조치를 수행할 수 있습니다. 장애 조치 시 Disaster Recovery는 재해 복구 사이트에 빈 데이터스토어를 자동으로 마운트하여 VM을 추가하고 장애 복구 작업을 위해 보호할 수 있도록 합니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["원격 사이트로 페일오버"^]을 참조하십시오.



===== vCenter 네트워크 자동 매핑

이제 vCenter 수준에서(즉, 복제 계획 대화 상자 외부에서) 네트워크 매핑 관계를 구성할 수 있습니다. 구성이 완료되면 Disaster Recovery에서 복제 계획을 추가하거나 편집할 때 이러한 네트워크 매핑을 자동으로 적용하여 복제 계획 관리를 간소화합니다.

재해 복구는 계획별 재정의를 계속 지원합니다. 복제 계획에 정의된 기존 네트워크 매핑은 네트워크별로 편집할 수 있으며, 이러한 매핑은 vCenter 수준의 정의보다 우선 적용됩니다.



==== 재해 복구 뷰어 역할 강화

재해 복구 뷰어 역할에서 '시스템 업그레이드' 탭을 볼 수 있는 기능이 제거되었습니다. 이러한 변경 사항은 읽기 전용 사용자에게 더 적합한 환경에 맞춰 역할을 조정하기 위한 것입니다. link:https://docs.netapp.com/us-en/console-setup-admin/reference-iam-disaster-rec-roles.html["NetApp Disaster Recovery에서 사용자 역할 및 권한에 대해 알아보세요."^].



==== 시스템 성능 향상

재해 복구에는 시스템 리소스 소비를 줄이고 운영 전반의 성능을 향상시키기 위한 변경 사항이 도입되었습니다.

==== 사용자 활동 알림에 대한 자동 응답

=== 디지털 어드바이저



==== Health Check GraphQL 마이그레이션 및 데이터 정확도 개선

상태 점검 모듈이 데이터 정확도 향상 및 최신 버전 표준에 맞춘 권장 사항 제공 기능을 통해 개선되었습니다. 이번 릴리스에서는 공개 API에서 GraphQL로 마이그레이션되어 성능 향상, 유연한 쿼리 기능 및 장기적인 지원을 제공합니다.



===== 추천 소프트웨어

Health Check 모듈의 권장 소프트웨어 개선 사항을 통해 더욱 정확하고 일관된 데이터를 제공합니다.

* 펌웨어 최신 버전 표시 아래의 셸프 및 드라이브 개수는 시스템별 정확한 값을 나타내며 더 이상 HA 페어 개수를 포함하지 않습니다.
* 최소 버전 및 최신 버전 권장 사항은 이제 최신 표준에 맞춰 클러스터 수준에서 유효 클러스터 버전을 기준으로 계산됩니다. 이전에는 이러한 권장 사항이 노드 수준에서 계산되었습니다.




===== AutoSupport 데이터 종속성

백엔드 개선으로 인해 AutoSupport 도입 및 권장 소프트웨어 보기가 최신 AutoSupport 데이터를 기반으로 합니다. 이로 인해 현재 보기에 다음과 같은 영향이 있을 수 있습니다.

[cols="30,70"]
|===
| 시나리오 | 영향을 받는 시스템 


| 표시된 데이터가 없습니다. | 2025년 10월 이후로 AutoSupport를 보내지 않은 시스템 


| 오래된 값 | 지난 30일 동안 AutoSupport를 전송하지 않은 시스템 
|===
위에 나열된 영향을 받는 시스템에서 AutoSupport를 다시 실행하여 상태 점검 보기의 현재 데이터를 복원하십시오.



[[keystone]]
=== Keystone

NetApp Console 의 Keystone 대시보드의 새로운 기능 향상:



==== MetroCluster 구독에 대한 ADP 라이선스 배포 내역 보기

이제 *고급 데이터 보호(ADP)* 탭에 새로운 *라이선스 배포* 하위 탭이 추가되어 MetroCluster 파트너 클러스터 전체의 ADP 라이선스 사용 현황을 확인할 수 있습니다. 자세한 내용은 https://docs.netapp.com/us-en/keystone-staas/integrations/adp-tab.html["Keystone MetroCluster 구독의 사용량 및 상태를 확인하세요"]을 참조하십시오.



==== 볼륨의 랜섬웨어 보호 상태 보기

자산의 *클러스터 내 볼륨* 탭에 이제 각 볼륨에 대해 자율 랜섬웨어 보호(ARP)가 활성화되었는지 비활성화되었는지 표시하는 *ARP 상태* 열이 추가되어 관리되는 자산 전체의 랜섬웨어 보호 상태를 파악할 수 있습니다. ARP에 대한 자세한 내용은 https://docs.netapp.com/us-en/ontap/anti-ransomware/["ONTAP의 ARP(Autonomous Ransomware Protection)"^]을 참조하십시오.



==== 피드백 탭을 사용하여 의견 공유

이제 Keystone 대시보드의 모든 화면에서 화면 오른쪽 하단에 고정된 새 *Feedback* 탭을 사용하여 피드백을 제공할 수 있습니다. 이 탭을 클릭하면 사용 경험을 공유하고 의견을 NetApp에 직접 제출할 수 있는 패널이 열립니다.



==== 용량 사용량 및 구독 만료에 대한 알림 개선

시스템에서 생성되는 모니터링 기능을 통해 용량 사용량 및 구독 만료에 대한 더욱 세분화된 알림을 받을 수 있습니다.

구독 만료와 관련하여 이제 알림은 만료일 180일, 90일, 60일, 30일, 7일 전의 다섯 가지 임계값에서 발생하며, 만료일이 가까워질수록 알림의 심각도가 정보 제공 수준에서 심각 수준으로 높아집니다.

용량 사용량에 대한 버스트 알림 임계값이 이제 고정된 20%가 아닌 구독의 약정 버스트 비율을 기준으로 합니다. 예를 들어 약정 버스트가 40%인 경우 약정 용량 사용률이 140%에 도달하면 심각한 알림이 발생합니다.

자세한 내용은 https://docs.netapp.com/us-en/keystone-staas/integrations/monitoring-alert-monitors.html["Keystone 구독에 대한 알림 모니터를 보고 생성하세요."]을 참조하십시오.

==== Kubernetes 워크로드 개선 사항

이번 릴리스에서 Kubernetes 워크로드는 다음과 같은 개선 사항을 도입했습니다.

* *Trident Protect 26.06*: 이번 릴리스에는 Trident Protect 26.06가 포함되어 있습니다.
* *복원 중 애플리케이션 생성 건너뛰기*: 이제 복원 작업 중 애플리케이션 사용자 지정 리소스 개체의 자동 생성을 건너뛸 수 있습니다. 이렇게 하면 애플리케이션 인벤토리에 불필요한 항목이 줄어듭니다.
* *VM 영구 볼륨 클레임 복원*: VM 기반 애플리케이션을 복원할 때 이제 전체 가상 머신을 복원하지 않고 개별 영구 볼륨 클레임을 복원할 수 있으므로 특정 디스크 또는 볼륨이 손상되거나 데이터가 손실된 경우 복구 속도가 향상됩니다.
* *작업 모니터링 개선 사항*: 이제 작업 모니터링을 통해 Kubernetes 보호 작업에 대한 가시성이 향상되었습니다. 작업 및 하위 작업에 대한 자세한 상태 정보를 확인하고 각 작업에서 사용되는 대상 스토리지를 볼 수 있습니다.


Kubernetes 워크로드 보호에 대한 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Kubernetes 워크로드 보호 개요"]을 참조하세요.

* *보호 그룹이 이제 호스트 시간대 스케줄링을 사용합니다*: 보호 그룹은 이제 Hyper-V 호스트의 시간대를 사용합니다. 호스트 시간대 스케줄링이 도입되기 전에 생성된 보호 그룹은 이전에 구성된 시간(일반적으로 UTC)을 계속 사용합니다. 이러한 보호 그룹이 Hyper-V 호스트 시간대를 사용하도록 업데이트하려면 스케줄을 다시 생성해야 합니다. 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-hyperv-protection-groups.html["Hyper-V 워크로드용 보호 그룹 생성 및 관리"]을 참조하십시오.


Hyper-V 워크로드 보호에 대한 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-hyperv-protect-overview.html["Hyper-V 워크로드 보호 개요"]를 참조하십시오.

=== 재해 복구



==== Kubernetes 업데이트

재해 복구 기능은 Kubernetes 기반 워크로드에 대해 다음과 같은 변경 사항을 도입했습니다.



===== Kubernetes 워크로드에 대한 페일오버 지원 테스트

재해 복구 기능이 이제 Kubernetes 워크로드에 대한 페일오버 프로세스 테스트를 지원합니다. 페일오버 테스트를 통해 재해 복구 계획의 유효성을 검증할 수 있습니다. 테스트가 완료되면 테스트 페일오버를 정리할 수 있으며, 시스템이 자동으로 테스트 리소스를 정리하여 오버헤드를 줄이고 환경의 일관성을 유지합니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html#test-the-failover-process["장애 조치 프로세스 테스트"^]를 참조하십시오.



===== 예약된 테스트 페일오버

이제 테스트 페일오버 일정을 설정하여 재해 복구 테스트를 자동화할 수 있습니다. 반복적인 테스트 페일오버 일정을 설정하여 수동 개입 없이 복구 계획을 지속적으로 검증하고, 복구 목표에 대한 신뢰도를 유지하며 규정 준수 요건을 충족할 수 있습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/manage.html#manage-replication-plans["복제 계획 관리"^]를 참조하십시오.



===== Kubernetes 워크로드의 예약된 검색

예약된 검색 기능을 사용하면 Disaster Recovery가 새로운 Kubernetes 워크로드를 검색하는 빈도를 제어할 수 있습니다. 운영 주기에 맞춰 검색 간격을 구성하면 불필요한 시스템 오버헤드를 줄이는 동시에 새로운 워크로드를 적시에 감지하고 보호할 수 있습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/sites-add.html#edit-the-site-and-customize-the-discovery-schedule["검색 일정 사용자 지정"^]를 참조하십시오.



==== VMware 업데이트



===== 빈 데이터 저장소 보호

보호 계획에 빈 데이터 저장소를 추가하는 경우, 장애 조치를 수행하기 전에 보호 계획에서 데이터 저장소를 제거하거나 강제 장애 조치를 수행해야 합니다. 자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["원격 사이트로 페일오버"^]를 참조하십시오.

이전에는 보호 대상에서 제외되었던 데이터 저장소를 이제 다시 포함할 수 있습니다. 이 개선 사항은 시간이 지남에 따라 재해 복구 구성을 관리하고 업데이트할 때 더 큰 유연성을 제공합니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/manage.html["사이트, 리소스 그룹 및 복제 계획 관리"^]를 참조하십시오.



===== VMFS 기반 데이터 저장소의 더 빠른 페일오버

재해 복구 기능이 VMFS 기반 데이터스토어의 페일오버 성능을 향상시켰습니다. Host Bus Adapter(HBA) 재검색 및 데이터스토어 마운트 작업이 이제 병렬로 실행되어 전체 페일오버 시간이 단축되고 복구 이벤트 중 다운타임이 최소화됩니다.

페일오버에 대한 자세한 내용은 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/use/failover.html["재해 복구를 통한 페일오버"^]을 참조하십시오.



[[ransomware-resilience]]
=== 랜섬웨어 복원력



==== 보호 전략을 위한 향상된 유연성

Ransomware Resilience은 이제 랜섬웨어 탐지 전략을 선택하는 데 더 많은 유연성을 제공합니다. 이전에는 모든 랜섬웨어 보호 전략에 암호화 탐지가 포함되어야 했습니다. 이제 사용자 행동 탐지만으로 구성된 랜섬웨어 보호 전략을 활성화할 수 있습니다.

보호 전략에는 암호화 감지_와_ 의심스러운 사용자 행동 감지가 모두 포함될 수 있습니다. 파일 확장자 차단 기능 또한 모든 보호 전략에 추가할 수 있습니다.

기존 정책의 보호 전략 일부를 비활성화하면 이전 정책 버전에서 생성된 기존 경고는 "해결됨"으로만 표시할 수 있으며 "무시됨"으로는 표시할 수 없습니다. 예를 들어 암호화 감지 및 의심스러운 사용자 동작을 포함하는 보호 전략이 있었지만 암호화 감지를 비활성화한 경우 해당 워크로드에 대한 기존 암호화 경고만 해결할 수 있습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/rp-use-protect.html["NetApp Ransomware Resilience 보호 전략으로 워크로드를 보호하세요"^]를 참조하십시오.



==== SOAR 플레이북 개선 사항

Ransomware Resilience SOAR 플레이북에 이제 사용자를 차단하거나 볼륨을 오프라인으로 전환한 후 복구 단계가 포함되어 있습니다. 해당 작업이 랜섬웨어 위협이 아닌 것으로 판단되면 볼륨을 다시 온라인 상태로 전환하고 사용자 차단을 해제할 수 있습니다.

link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/reference-soar.html["SOAR 플레이북 통합"^].



[[cloud-volumes-ontap]]
=== Cloud Volumes ONTAP



==== AWS의 Cloud Volumes ONTAP용 새 EC2 인스턴스 지원

Cloud Volumes ONTAP 9.16.1 이상 버전은 AWS에서 신규 및 기존 단일 노드와 고가용성(HA) 쌍 배포 모두에 대해 M6id 및 M6idn EC2 인스턴스 제품군을 지원합니다. 이러한 6세대 인스턴스는 5세대 범용 시스템에 비해 더 빠른 처리 속도, 강력한 네트워킹 기능 및 향상된 성능을 제공합니다.

* *M6id 인스턴스*: 고속 저지연 로컬 NVMe 스토리지를 통해 컴퓨팅 성능과 메모리 용량의 균형을 제공합니다. 모든 M6id 인스턴스 크기는 Flash Cache를 지원합니다. 이러한 인스턴스는 데이터 로깅 및 미디어 처리와 같은 워크로드에 적합합니다.
* *M6idn 인스턴스*: M6id 인스턴스와 동일한 로컬 NVMe 스토리지 기능을 제공합니다. 모든 M6idn 인스턴스 크기는 Flash Cache를 지원합니다.


고성능 또는 메모리 집약적인 워크로드에는 m6id.xlarge, m6id.2xlarge, m6idn.xlarge 및 m6idn.2xlarge 인스턴스 유형을 권장하지 않습니다. 이러한 워크로드에는 코어 개수와 메모리 용량이 더 큰 인스턴스 유형을 사용하십시오.

자세한 내용은 https://docs.netapp.com/us-en/cloud-volumes-ontap-relnotes/reference-configs-aws.html["AWS에서 Cloud Volumes ONTAP에 대해 지원되는 구성"^]을 참조하세요.

[[cloud-volumes-ontap]]
=== Cloud Volumes ONTAP



==== AWS의 Cloud Volumes ONTAP 및 데이터 서비스에 대한 유연한 요금 청구

NetApp은 AWS에서 Cloud Volumes ONTAP 구독에 대한 향상된 청구 옵션을 제공하여 Cloud Volumes ONTAP 용량 및 NetApp Backup and Recovery와 같은 NetApp 데이터 서비스 비용 지불 방식을 더욱 세밀하게 제어할 수 있도록 지원합니다. 이전에는 모든 Cloud Volumes ONTAP 및 데이터 서비스 사용량이 AWS 마켓플레이스의 NetApp Intelligent Services(NIS) 목록을 통해 통합적으로 청구되었습니다.

AWS 엔터프라이즈 할인 프로그램(EDP) 변경으로 인해 NetApp은 AWS 마켓플레이스에 독립형 Cloud Volumes ONTAP 구독을 출시했습니다. 이를 통해 Cloud Volumes ONTAP 용량과 데이터 서비스 요금을 분리하여 청구할 수 있습니다. 이러한 분리를 통해 EDP 크레딧 및 비용 관리에 있어 더욱 유연성을 확보할 수 있습니다. NetApp은 Cloud Volumes ONTAP 사용량에 대한 비용 관리를 개선하기 위해 독립형 구독을 사용하는 것을 권장하며, EDP 요건이 적용되는 2026년 7월 31일 이후에는 데이터 서비스 요금 청구를 위해 NIS 구독을 계속 사용할 것을 권장합니다.

AWS의 독립형 Cloud Volumes ONTAP 구독은 유효한 용량 기반 Essentials 또는 Freemium 라이센스 패키지만 지원합니다. Professional 패키지는 지원되지 않습니다. 필요에 가장 적합한 청구 방법을 선택할 수 있습니다.

* *독립형 Cloud Volumes ONTAP 구독(권장)*: AWS 마켓플레이스에서 독립형 구독을 통해 Cloud Volumes ONTAP 사용량에 대한 비용을 지불하고, 데이터 서비스 요금은 NIS 구독을 통해 계속 청구됩니다. 이 옵션은 NetApp Console의 AWS 계정에 독립형 및 NIS 구독이 모두 연결된 대부분의 고객에게 권장됩니다.
* *통합 NIS 구독*: 기존 NIS 목록을 통해 Cloud Volumes ONTAP과 데이터 서비스를 함께 결제하세요. 이 통합 방식은 NetApp Console에서 AWS 계정에 NIS 구독만 연결된 기존 고객에게 적용됩니다. 하지만 NetApp은 더 나은 비용 관리를 위해 Cloud Volumes ONTAP 사용량에 대한 결제 기본 설정을 지정하고 독립형 구독으로 전환하는 것을 권장합니다.


구독 유형에 따라 다음과 같은 시나리오가 제공됩니다.

.독립형 구독만 가능(신규 고객)
NetApp Console의 AWS 계정에 독립형 AWS 구독만 연결되어 있고 NIS 구독이 없는 경우, 배포 시 Essentials 라이선스 패키지만 선택할 수 있습니다. 데이터 서비스 *Backup and Recovery* 옵션을 사용할 수 없습니다.

.독립 실행형 및 NIS 구독(기존 고객) 모두
AWS 계정에 NIS 구독과 독립 실행형 구독이 모두 연결되어 있고 NetApp Console의 *청구 기본 설정* 탭에서 청구 기본 설정을 지정하지 않은 경우 Cloud Volumes ONTAP 사용량은 기본적으로 NIS를 통해 청구됩니다. 독립 실행형 목록에서는 Professional을 지원하지 않으므로 Professional 패키지를 실행하는 모든 Cloud Volumes ONTAP 인스턴스에서도 기본적으로 이 방식이 적용됩니다. 청구 기본 설정을 지정하여 각 서비스에 대한 청구 방식을 선택할 수 있습니다.

* 독립형 구독을 Cloud Volumes ONTAP(Essentials 패키지 포함)의 기본 결제 계정으로 설정하세요. Professional 패키지만 있는 경우 Essentials 패키지로 전환하고 결제 기본 설정을 지정하여 Cloud Volumes ONTAP 사용량을 청구할 수 있습니다. 이 방법은 Cloud Volumes ONTAP EDP 크레딧을 보다 효과적으로 관리하는 데 도움이 되므로 권장합니다.
* NIS 구독을 사용하여 데이터 서비스 요금을 청구하거나 Professional 패키지를 통해 Cloud Volumes ONTAP 사용량을 청구합니다. 배포 중에 *Backup and Recovery* 데이터 서비스를 활성화하고 Professional 라이센스 패키지를 선택하여 NIS 구독을 통해 데이터 서비스 요금을 청구합니다.


.NIS 구독 전용(기존 고객)
이는 AWS 계정과 연결된 NIS 구독을 보유한 기존 고객에게 적용됩니다. 현재와 같이 Cloud Volumes ONTAP과 데이터 서비스를 함께 청구할 수 있습니다. 하지만 NetApp은 Cloud Volumes ONTAP 사용량에 대한 비용 관리를 개선하기 위해 독립형 구독 방식으로 전환하는 것을 권장합니다.

* AWS 포털에서 새로운 독립형 목록을 구독하세요.
* 독립형 구독을 AWS 계정에 연결하세요.
* Essentials 패키지를 사용한 Cloud Volumes ONTAP 사용에 대해 결제 기본 설정을 독립형 구독으로 설정하십시오.
* (해당되는 경우) Professional 패키지를 Essentials 패키지로 변경하고 결제 방식을 설정하세요.
* NIS 구독을 통해 데이터 서비스 요금 청구를 계속 진행하십시오.



NOTE: 여러 구독 유형을 사용하거나 목록 간에 마이그레이션하는 경우 중복 측정이 발생하지 않습니다.

[[disaster-recovery]]
=== 재해 복구



==== Kubernetes 기반 워크로드 지원(미리 보기)

NetApp Disaster Recovery에 Kubernetes 기반 워크로드 지원이 추가되었습니다. Kubernetes 지원을 통해 OpenShift Virtualization 환경을 포함한 Kubernetes 클러스터에서 실행되는 애플리케이션을 보호할 수 있습니다. Disaster Recovery는 link:https://docs.netapp.com/us-en/trident/trident-protect/trident-protect-requirements.html["Trident Protect에서 현재 지원하는 모든 Kubernetes 버전"^]를 지원하여 컨테이너화된 애플리케이션에 대한 원활한 통합과 강력한 재해 복구 기능을 제공합니다.

Kubernetes 기반 워크로드 지원의 주요 기능:

* **폭넓은 호환성**: Disaster Recovery는 Red Hat OpenShift Virtualization을 포함하여 Trident Protect와 호환되는 모든 Kubernetes 버전을 지원합니다.
* **애플리케이션 중심 보호**: 이제 애플리케이션 수준에서 Kubernetes 워크로드를 보호하여 페일오버 이벤트 발생 시 중요한 서비스의 복구를 보장할 수 있습니다.
* **간소화된 오케스트레이션**: Disaster Recovery는 VMware 환경에서 사용되는 것과 동일한 효율적인 SnapMirror 기술을 활용하여 Kubernetes 워크로드의 백업 및 복제를 자동화하는 직관적인 워크플로우를 제공합니다.


Kubernetes 기반 워크로드 지원은 현재 미리 보기로 제공됩니다. Kubernetes 기반 워크로드 보호를 시작하려면 link:https://docs.netapp.com/us-en/data-services-disaster-recovery/get-started/task-kubernetes-requirements.html["NetApp Disaster Recovery를 위한 Kubernetes 요구 사항"^]을(를) 참조하십시오.



[[ransomware-resilience]]
=== 랜섬웨어 복원력



==== 클린 복원 기능 향상

이제 클린 복원 기능을 통해 다른 위치로 복구할 수 있습니다. 이를 통해 동일한 Console 에이전트에서 관리하는 다른 시스템, 스토리지 VM 및 애그리게이트로 볼륨을 복원할 수 있습니다. 또한, 클린 복원 기능은 복구에 사용할 수 있는 스냅샷을 검색하는 데 적용되던 7일 제한을 해제했습니다. 이제 클린 복원 기능은 랜섬웨어 발생 시점과 관계없이 사용 가능한 스냅샷을 지속적으로 검색하여 복구 지점을 찾습니다.

link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-clean-restore-recover.html["깔끔한 복원을 통해 워크로드 복구"^].



==== Google SecOps SIEM 지원

Ransomware Resilience는 이제 Google SecOps를 통한 보안 정보 및 이벤트 관리(SIEM)를 지원하므로 간소화된 위협 분석 및 탐지를 위해 데이터를 Google SecOps로 자동으로 전송할 수 있습니다.

구성 정보는 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/task-siem.html["Ransomware Resilience를 SIEM에 연결하세요"^]을(를) 참조하십시오.



==== Azure NetApp Files 지원이 이제 정식으로 제공됩니다

Ransomware Resilience는 이제 Azure NetApp Files 시스템을 지원하여 Azure NetApp Files에서 랜섬웨어 위협을 효율적으로 탐지하고 대응할 수 있습니다. 워크로드를 검색할 때 Ransomware Resilience는 이제 Azure NetApp Files를 표시하고 보호 대시보드에 표시합니다. Azure NetApp Files에 대한 Ransomware Resilience 지원에는 스냅샷만을 사용한 탐지 및 보호 전략이 포함됩니다. Azure NetApp Files 지원은 현재 정식 출시(GA)되었습니다.

자세한 내용은 link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/concept-ransomware-resilience.html["랜섬웨어 복원력에 대해 알아보세요"^]를 참조하십시오.



==== SOAR의 사용자 차단 지원

Ransomware Resilience이 이제 Google SecOps 및 Splunk SOAR 플레이북을 사용하여 개별 사용자 차단을 지원합니다. 이 추가 기능을 통해 Ransomware Resilience에서 데이터 유출이나 대량 데이터 삭제와 같은 의심스러운 사용자 활동을 감지할 때 사용자 차단을 자동화할 수 있습니다.

link:https://docs.netapp.com/us-en/data-services-ransomware-resilience/reference-soar.html["SOAR 플레이북 통합"^].

==== Kubernetes 워크로드 개선 사항

이번 릴리스에서 Kubernetes 워크로드는 다음과 같은 개선 사항을 도입했습니다.

* *Trident Protect 26.05*: 이번 릴리스에는 Trident Protect 26.05가 포함되어 있습니다.
* *백업 및 복구에서 Trident Protect 업그레이드*: Kubernetes 클러스터에서 Trident Protect 26.05 이상을 실행 중인 경우 이제 백업 및 복구에서 직접 Trident Protect를 업그레이드할 수 있습니다.
* *VM 보호를 위한 기본 지원*: 이제 VM 기반 애플리케이션을 생성하여 다른 애플리케이션과 동일한 방식으로 가상 머신을 보호할 수 있습니다.
* *리소스 변환*: 이제 리소스 변환 및 리소스 변환 템플릿을 사용하여 복원 프로세스 중에 리소스 속성을 추가, 제거 및 수정할 수 있습니다.
* *보호된 리소스 보기*: 이제 애플리케이션의 각 복구 지점에 포함된 리소스를 확인하고 자세한 JSON 보고서를 다운로드할 수 있습니다. 이를 통해 복구 지점을 완벽하게 파악하고 감사 규정 준수를 간소화할 수 있습니다.


Kubernetes 워크로드 보호에 대한 자세한 내용은 https://docs.netapp.com/us-en/data-services-backup-recovery/br-use-kubernetes-protect-overview.html["Kubernetes 워크로드 보호 개요"]을 참조하세요.
